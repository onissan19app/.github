# Contribuer

Merci de contribuer. Chaque dépôt peut compléter ces consignes avec son propre guide, sa stack et ses commandes.

## Avant de commencer

- Pour une évolution ou un défaut non urgent, ouvre ou retrouve une issue qui décrit le problème, le résultat attendu et les critères d’acceptation.
- Si le besoin ou le périmètre est ambigu, clarifie-le avant de modifier le code.
- Consulte le README et les instructions du dépôt concerné.

## Préparer le changement

- Crée une branche de travail depuis la branche par défaut. Préfixes conseillés : `feat/`, `fix/`, `docs/`, `chore/`.
- Garde le changement cohérent et aussi limité que possible.
- N’inclus pas de secrets, de données personnelles ou de fichiers générés sans raison.

## Vérifier et ouvrir une pull request

- Lance les vérifications demandées par le dépôt : formatage, analyse statique, tests et build selon le changement.
- Ajoute ou adapte les tests pour le comportement modifié.
- Mets à jour la documentation affectée.
- Ouvre une pull request vers la branche par défaut et relie l’issue correspondante.
- Décris le problème, la solution, les vérifications exécutées et les risques connus. Pour un changement d’interface, ajoute des captures ou une courte démonstration quand c’est utile.

Une pull request est prête à être examinée lorsque son périmètre est clair, ses vérifications sont rapportées et les points bloquants sont résolus. Les règles spécifiques du dépôt et les contrôles GitHub configurés pour celui-ci s’appliquent également.
